## Dashboard sync spec (normative: used ONLY when the three files cannot be copied from the v1.9.5 clone; implement all of it)
Purpose: when the dashboard is refreshed in Fathom and new records load, the S3 copy must reflect them. A refresh does not change the dashboard HTML, so S3 gets (1) the data the dashboard received, in the data folder, and (2) a snapshot HTML that replays that data. Nothing here ever deletes anything.

**`scripts/recovery_hook.js`** (browser code; one IIFE; no `</script` text anywhere in it)
- Do nothing if `window.FathomRecovery` already exists. Options read from `window` before it runs: `FATHOM_RECOVERY_AUTO` (false = no capture), `FATHOM_RECOVERY_DEBOUNCE_MS` (default 4000), `FATHOM_RECOVERY_MAX_BYTES` (default 5 MB), `FATHOM_RECOVERY_NAME_BY_ARGS` (default true), `FATHOM_RECOVERY_SYNC_SCRIPT` (default `scripts/recovery_sync.py`).
- It is installed at the TOP of the page so it runs before the dashboard's own scripts. It wraps `window.Panel.runFile`, `readFile` and `readData`. If `window.Panel` does not exist yet it defines a setter trap on `window.Panel` that wraps it the moment the page assigns it, and also polls every 250 ms (up to 80 tries).
- For every response with `success !== false` it remembers `responses["<method>|<path>|<args>"] = {t: <ms>, r: <response>}` (args = the `args` option of runFile as a string, else JSON; empty for readFile/readData). Skip responses larger than the max size. Skip a response identical (JSON text) to the one already remembered for that key.
- For a `runFile` response with `result.exit_code` 0 (or absent) and non-empty `result.stdout` (never for the sync script itself) it also saves the stdout as an inbox file named `<path with / and \ replaced by _, extension removed>[_<hash of args>]` with extension json if the text parses as JSON, else txt.
- Debounced flush (one sync per burst of calls; if a flush is running, run again afterwards): write each pending file with `window.Panel.writeFile(".fathom_recovery/inbox/<name>__<Date.now()>.<ext>", text, {mimeType})`; if responses changed write the whole responses map as `.fathom_recovery/inbox/dashboard_responses__<ms>.json`; then call the ORIGINAL `runFile(SYNC_SCRIPT, {timeout: 900})`, parse the last stdout line as JSON, and log `[FathomRecovery] sync ok` or `PROBLEM` with that result. If `window.Panel` is not ready, retry in 1 s. A page load or refresh schedules one sync once Panel exists.
- Public API: `window.FathomRecovery = {save(name, dataOrString), sync(), state, installed()}`; `state = {syncs, saved, remembered, lastResult, lastError}`. `save` sanitizes the name to `[A-Za-z0-9._-]` (max 100) and ignores empty or oversize data. Errors are caught and logged, never thrown into the dashboard.

**`scripts/recovery_sync.py`** (Python 3, standard library only; ROOT = parent of the folder holding the script)
- Needs `scripts/fathom_recovery.py` and `recovery_config.json`, else prints a JSON error and exits 1. Takes an exclusive file lock (`fcntl.flock`, lock file in the temp dir named from a hash of ROOT, wait up to 120 s) so two syncs never overlap. Flags `--dry-run` (sweeps run without `--apply`, nothing uploaded) and `--no-code` (skip the code sweep).
- Inbox `.fathom_recovery/inbox/<name>__<digits>.<json|txt>`: reject (list in `inbox_rejected`, leave in place) names not matching, names whose `<name>` is not `[A-Za-z0-9][A-Za-z0-9._-]{0,100}`, and empty files. Process oldest first so the newest wins. `<name>` other than `dashboard_responses` is renamed (`os.replace`) to `<output_dir>/dashboard_data/<name>.<ext>`. `dashboard_responses` files are MERGED into `<output_dir>/dashboard_data/dashboard_responses.json` (`{"responses": {...}, "updated_utc": ...}`): a call's entry is replaced only when its response differs; `updated_utc` changes only when something changed; the consumed inbox file is then removed (it is only a hand-off file, never in S3); invalid JSON is rejected. Writes are atomic (temp file, then rename).
- Snapshot (only if `dashboard_responses.json` exists): find the dashboard with the same discovery rule as the installer; read it as UTF-8 (on failure report `error`, ok=false); remove the hook block; if what is left does not start (after optional whitespace and a doctype) with an `<html` tag, i.e. it is a FRAGMENT dashboard, wrap it as `<!doctype html><html><head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1"></head><body><div class="panel-body">` + the text + `</div></body></html>` (Fathom renders fragments inside `.panel-body`, so CSS scoped to it must still apply when the snapshot is opened outside Fathom; a full document is NOT wrapped); insert, in the same top position, a snapshot block containing the shim below with the responses data embedded (escape `</` as `<\/` and `<!--` as `<\!--` inside the JSON); write it to `<output_dir>/dashboard_snapshot/<dashboard file name>` ONLY if the bytes changed.
- Then run `fathom_recovery.py sweep --config recovery_config.json --state-file .fathom_recovery/state.json [--apply]` and (unless `--no-code`) `code-sweep` with `.fathom_recovery/code_state.json`, from ROOT, parse the `SUMMARY` line, and print exactly ONE JSON line: `{ok, dry_run, captured_files, inbox_rejected?, snapshot: {source, file, written, responses, data_as_of} | {skipped, candidates?} | {error}, sweeps: [{command, exit_code, ok, uploaded, unchanged, failed, output_tail?}], error?}`. Exit 0 only if every sweep succeeded and the snapshot has no error.

**`scripts/install_dashboard_hook.py`** (Python 3, standard library only; dry run unless `--apply`)
- Usage: `[html] [--apply] [--remove]`. With no file name it discovers the dashboard under ROOT, skipping dirs `.git node_modules .venv venv __pycache__ site-packages knowledge .fathom_runtime .fathom_recovery restored_code dashboard_snapshot`; candidates are `.html`/`.htm` files; choose the only HTML file; else the only file whose name contains "dashboard"; else the only file containing `window.Panel`; else print the candidates, change nothing and exit 2.
- The hook is ONE block `<!-- fathom-recovery-hook:start -->\n\n<contents of recovery_hook.js>\n\n<!-- fathom-recovery-hook:end -->\n`. Any existing block is removed first, so a second run replaces it and `--remove` restores the original bytes. Insert the block at the TOP: right after the `<head ...>` tag, else after `<html ...>`, else after a doctype, else at the very start (fragment dashboards). Refuse if the hook JS contains `</script`. Print the action and `size -> size, sha256-prefix -> prefix`; if the result equals the file print "already up to date"; without `--apply` print "dry run: nothing written"; with it write atomically (temp file, rename).
- The shim (placed in the snapshot block, not in the live dashboard): defines `window.Panel` ONLY if none exists (or `window.FATHOM_SNAPSHOT_FORCE` is set), so inside Fathom the live Panel is untouched. Its `runFile/readFile/readData` return the remembered response for the exact key (`<method>|<path>|<args>`), else the newest remembered response for the same method and path, else `{success: false, error: "not captured in this snapshot (...)"}`; `writeFile` returns `{success: true, snapshot: true}`; it sets `window.FATHOM_SNAPSHOT = {updated_utc, responses: <count>}`.

**`scripts/recovery_watch.py`** (Python 3, standard library only; Linux/macOS because of `fcntl`; ROOT = parent of the folder holding the script; needs `scripts/fathom_recovery.py` and `scripts/recovery_sync.py` next to it and `recovery_config.json` in ROOT, else it prints a message and exits 1)
- It loads `fathom_recovery.py` and `recovery_sync.py` from its own folder (`importlib`, no `__pycache__`) and reuses their skip rules (`CODE_SKIP_DIRS`, `CODE_SKIP_ROOT_DIRS`, `MAX_CODE_BYTES`, `sensitive_name`) and their `sweep(command, state_name, apply)`, `acquire_lock` and `atomic_write`, so what it watches is exactly what the code sweep could upload.
- Files in the temp dir named from the first 12 hex chars of sha256(ROOT): `fathom_recovery_watch_<tag>.lock` (one watcher per workspace, `fcntl.flock` non-blocking; a second watcher logs "another watcher is already running for this workspace; exiting" and exits 3), `.status.json`, `.stop`.
- **Scan** (stat only, never hashes): `{relative path: (mtime_ns, size)}` over ROOT without following symlinks, skipping dirs `CODE_SKIP_DIRS` plus `.fathom_recovery`, `.fathom_runtime`, root-level `restored_code`, and config key `code_exclude_dirs`; skipping symlinks, `*.tmp`, `.tmp_*.json`, files over `MAX_CODE_BYTES`, sensitive names, and names not matching config key `code_patterns` (default `["*"]`). Every EMPTY folder (no sub-folders and no files, other than ROOT) is tracked as the key `<path>/` with value `(0, 0)`. `.fathom_recovery/` is skipped on purpose: the sweeps' own state files must never trigger a sweep.
- **User pinning** (before anything else, for `--once` and for watching; not for `--status` / `--stop`): resolve the `<user>` folder ONCE with `fathom_recovery.resolve_user(None)` and set `os.environ["RECOVERY_USER"]` to it, so every sweep subprocess uses the same folder. If it resolves to `unknown-user` and `RECOVERY_USER` was not set explicitly, print a message containing "unknown-user" and "Refusing to run", upload nothing and exit 1: a long-lived process can lose `bridge.whoami()`, and then every sweep would silently upload to the wrong `unknown-user` folder and record those files as uploaded. The start log line says `user folder pinned to '<user>'` and the status file has `user_folder`.
- **Loop** (`--interval` seconds, default 5). On start: one scan, then a baseline sweep right away. Each pass: stop if the `.stop` file exists or `--max-runtime` is exceeded; scan; if the scan differs from the previous one, log `changed: <up to 5 paths> (+N more)` for new or modified entries, mark dirty and remember the time. Mark dirty also when `--full-every` seconds (default 900, 0 = off) passed since the last good sweep, log `periodic full sweep`. When dirty AND `--quiet` seconds (default 3) passed without further changes AND the retry time has passed: run the data sweep (`sweep`, `state.json`) then the code sweep (`code-sweep`, `code_state.json`) under `acquire_lock(120)`, with `--apply` unless `--dry-run`. After a sweep scan again: if anything changed during the sweep (compare with the scan taken before it), stay dirty. Write the status file after every pass.
- **Result**: ok only if every sweep result is ok. Ok: clear dirty and backoff, log `sweep ok: <json of command/ok/uploaded/unchanged/failed/exit_code per sweep>`. Not ok (S3 error, missing credentials, lock timeout, any exception): never exit; count a failure, log `sweep PROBLEM (retry in Ns): <first 600 chars>`, retry after `max(--retry-min, 2 x previous delay)` seconds, default 30, capped at 600.
- **Status file** keys: `pid, root, started_utc, sweeps, failures, last_sweep_utc, last_ok, last_result, tracked_files, dry_run, user_folder, heartbeat_utc`, plus `stopped_utc` on exit.
- **Commands/flags**: `--interval`, `--quiet`, `--full-every`, `--retry-min`, `--max-runtime`, `--dry-run`; `--status` prints JSON `{running, status}` (running = the lock is held by another process) and exits 0; `--stop` creates the `.stop` file if a watcher is running ("stop requested; the watcher exits within one scan interval") else prints "no watcher is running"; `--once` runs the two sweeps once, prints ONE JSON line `{ok, sweeps}` and exits 0 only if ok; `--log PATH` appends all output to PATH (line-buffered, UTF-8) and REFUSES (message "--log must be OUTSIDE the workspace ...", exit 1) a path that resolves (`realpath`, so `..` and symlinks count) to ROOT or inside it, because a log inside the workspace would be swept and re-trigger sweeps.
- **Safety**: no delete or lifecycle calls anywhere; it deletes no local file; it never edits workspace files; a file deleted or renamed locally keeps its S3 copy.
